装配属性回归测试
================

在 Xcode 中运行
--------------
1. 打开 EVE Nexus.xcodeproj，选择 EVE Nexus scheme 和可用的 iOS 模拟器。
2. 按 ⌘6 打开 Test Navigator，展开 EVE NexusTests。
3. 点击 FittingRegressionTests 和 FittingCalculationTests 旁边的运行按钮。
4. 在测试结果中查看失败断言；完整快照和差异见测试报告附件。
无需额外脚本。⌘U 会运行 scheme 中的全部测试，包括其他功能测试。
日常比对不要设置 EVE_FITTING_CANDIDATE_DIR 环境变量：该变量是候选导出开关，
设置后场景测试会跳过已保存基准的比较。下文使用 Xcode 报告附件维护基准，无需设置它。

测试文件与职责
--------------
- FittingRegressionTests.swift：场景测试入口、语义断言和跨装配缓存隔离检查。
- FittingSnapshot.swift：真实 SDE 准备、结果归一化、指纹和属性差异比较。
- FittingRegressionFixtures.json：原生装配输入、场景说明和人工操作步骤。
- Baselines/FittingSnapshot-S01.json 至 S20.json：按场景保存的已审阅预期结果。
- ../FittingCalculationTests.swift：独立的公式与边界测试，不依赖快照替代正确性断言。
- ../FittingSaveSnapshotTests.swift：持久化内容比较，验证字段覆盖、顺序归一化和身份隔离。

改动前后如何比较
----------------
1. Baselines 中保存各场景已审阅的预期结果；回归比较应结合独立断言，
   基准本身不能证明游戏数值完全正确。
2. 后续优化前先运行上述两个测试类确认绿灯，保留这些测试数据和基准，再改生产代码。
3. 改动后再次运行；纯性能优化应全部通过。失败信息给出场景、槽位、属性 ID/名称、旧值、新值和差额。
4. 每个场景的 FittingSnapshot-Sxx-actual.json 都附在 Xcode 测试报告中；失败另有完整 diff.txt。
   断言信息只列前 30 条差异，完整内容查看附件。
5. 对于有意修复的数值变化，先审阅差异，确认新结果与独立公式/预期相符。
   从测试报告导出相应的 FittingSnapshot-Sxx-actual.json 附件作为候选，测试不会自动覆盖基准。
6. 确认后将候选改名为 FittingSnapshot-Sxx.json，替换 Baselines 下对应文件，再运行测试。
   不要为消除红灯直接更新基准。代码修复与获准的基准差异一起提交，方便后续追溯。

SDE 版本与升级维护
-----------------
每次验证代码改动前后结果时，SDE、装配输入和技能条件必须保持一致。
这不代表永远冻结 SDE：测试跟随仓库内置版本升级，但数据升级与算法修改应分开验证。
当前数据源是 EVE Nexus/utils/sde/sde.zip，不使用测试设备的 OTA 版本作为基准来源。
每个快照包含 schema、sdeSHA256 和 fixturesSHA256；最后两个分别校验整个 ZIP 和装配 JSON 的字节。
因此，即使只是重新打包 ZIP 或调整装配 JSON 的说明/格式，也会触发指纹差异，需确认原因。

升级流程：
1. 在旧 SDE 和旧基准下运行两个测试类，确认当前代码通过。
2. 保持计算代码不变，更新内置 SDE 及项目要求的配套元数据；重新构建并运行测试。
3. 此时 SDE 指纹不匹配属于预期失败，但仍需检查完整属性差异及独立语义断言。
   检查船体/模块数值、技能清单、效果定义、类型兼容性是否与数据更新一致。
4. 若出现不能解释的变化，先定位数据或代码原因；不要仅修改快照内的哈希来让测试通过。
   如果新数据确实要求代码适配，应单独说明并验证对应逻辑变化。
5. 审阅全部场景，从 Xcode 报告导出新的实际快照，替换 Baselines 下的对应文件。
   SDE 指纹存在于每个场景中，因此即使某些场景数值未变，也需要更新全部场景基准。
6. 再运行两个测试类，确认通过；一起提交 SDE 更新、基准和变更说明。
   说明中记录 SDE 来源/版本、旧新哈希、主要属性变化原因、验证结果及仍存在的已知边界。

算法优化只接受容差内结果不变；修复错误则需要独立公式或明确规则支持新值，
并补充针对该错误的语义断言，再审阅和更新受影响基准。快照相同只能说明行为未回归。

新增或修改测试装配
------------------
1. 在 FittingRegressionFixtures.json 中维护唯一 case id、scenario、kind 和原生 fitting 数据。
   优先增加单一差异的成对场景，例如模块开/关、装弹/卸弹、环境有/无，并写清预期。
2. 新增场景时，在 FittingRegressionTests 中增加调用 check("Sxx") 的测试方法；
   仅在 JSON 中添加一个新 scenario 不会自动创建 XCTest 方法。
3. 数量改变时，同步更新 FittingRegressionData 初始化中的装配数量和唯一 ID 数量断言
   （当前均为 48），以及 README 中的清单统计，保留防止漏装配的检查。
4. 为新增规则增加独立断言。正常装配不应被安装校验剔除模块；非法输入应明确断言拒绝、
   降级或资源超限行为，不能只保存错误输出作为“正确结果”。
5. 运行测试并审阅附件。首次添加场景时缺少基准会报错，实际快照已在读取基准前生成，
   可导出审阅后作为初始基准。不要自动把首次输出认定为正确结果。
6. 装配 JSON 使用全文件指纹，任何修改都会影响所有场景的 fixturesSHA256；
   因此需检查全部场景并更新全部基准，确认无关场景数值没有意外变化，然后复跑。
7. 如果改变快照结构或比较规则，同步审阅 schema 版本和比较器测试；
   不要通过增大浮点容差、删除失败字段或跳过用例来掩盖无法解释的差异。

常见失败的处理
--------------
- SDE/fixture 指纹变化：先确认数据是否被有意修改，再按相应维护流程审阅全部场景。
- 同一数据下数值、状态或属性集合变化：定位生产代码差异，纯优化应恢复一致。
- 缺少测试资源：检查 JSON 是否进入 EVE NexusTests 的构建资源，不要把失败改成跳过。
- SDE 加载或全 5 技能清单不完整：检查内置 ZIP 和解压后的库，禁止用空数据生成基准。
- 跨装配复算不一致：检查计算器缓存和输入污染，不能仅更新快照解决。
- 语义断言失败：先判断规则或输入是否发生有意变化，单独修正原因并验证。

固定条件与计算路径
------------------
FittingRegressionFixtures.json 包含 48 个原生装配，运行时不依赖个人目录。
44 个正常装配、3 个非法装配、1 个建筑服务槽边界，分为 S01–S20。
测试使用 App 内置 sde.zip，重播到测试宿主的模拟器 Documents/sde，完整加载真实 SDE 索引。
DEBUG 单元测试宿主跳过日常 App 启动，避免后台 SDE 初始化/OTA/账号任务与测试并发；
正常运行、UI 测试宿主和 Release 不走这一分支。建议使用测试专用模拟器。
该分支位于 EVE_NexusApp.swift，通过 DEBUG 下的 XCTestCase 类检测识别单元测试宿主。
它会跳过常规初始化并展示空视图，使测试独占数据准备流程，避免启动页再次加载 SDE、
后台更新或账号任务干扰测试。作用范围是所有 XCTest 单元测试，不只装配回归测试；
其他依赖启动数据的单元测试也必须显式准备数据，不能依赖 App 的异步启动碰巧完成。
固定已发布技能全 5、各装配指定的状态/环境/突变/弹药，注电备用弹药无限，换弹时间保留。
SDE ZIP 与装配数据 SHA256 写入每个基准，任何数据源变化都会报错，避免混淆数据更新与代码变化。

真实调用路径：
  LocalFitting 解码
  → FittingEditorViewModel(temporaryFitting:..., characterSkills:全5)
  → FitConvert.localFittingToSimulationInput
  → processConfiguration 安装检查
  → calculateAttributes：AttributeCalculator Step1–5
    → validateGroupLimitsAfterCalculation；发生状态降级时补算，直至限制满足
  → 输出快照 + FittingCapacitorCalculator + FittingWeaponStatistics
属性快照不使用手工 SDE 替身，不写入装配文件、不自动保存到角色账号。
手动保存与移除指挥处理器测试会在测试宿主中写入随机 UUID 的本地装配，结束后清理该测试副本。

比较内容
--------
船体、角色、计算后的技能属性、每个槽位模块和已装弹药、无人机组、舰载机中队（按轻型/重型/辅助管识别）、
植入体、环境、货舱数量/体积；模块状态、装弹数量、突变后类型、被拒绝模块。
ID 属性表与供 UI 使用的名称索引均保存；随机实例 UUID、显示名称、图标、时间戳不参与比较。
模块按槽位识别，无人机/货舱按原生文件中的稳定数组位置区分同型多组，舰载机还标记 tubeId。
电容稳定性、稳定低点、耗尽/验证时长、净变化和达到模拟上限的状态均比较。
无穷稳定时长编码为明确的字符串，其他非有限数值直接报错。
换弹统计以单位齐射量调用真实换弹 helper，检查周期/弹仓/换弹行为，不复制 UI 总 DPS 公式。
数值容差：|new-old| <= 1e-8 + 1e-9 * max(|new|, |old|)。新增/缺失属性也是失败。
类型、数量和状态等标签严格比较，不使用浮点容差。

独立断言
--------
- 零备用注电与有备用的电容结果相同，吸电/注电必须有实际周期，注电保留换弹。
- 吸电和注电分别延长无供能装配的持续时间。
- 武器满预热伤害符合 damageMultiplierBonusMax 倍率。
- 三神遥修满预热修量符合 repairMultiplierBonusMax 倍率；普通遥修、本舰属性、耗电与周期不变。
- 原生保存/重载保留全部 0–3 状态；EFT/DNA 和在线装配的未指定状态使用默认在线/激活，DNA 显式离线仍保留。
- 缺失的 T3 驱逐舰默认模式会完整加载属性与效果，与显式安装相同模式的计算结果一致。
- 不兼容模块被拒绝；双损伤控制明确保留 LoSlot0 在线、LoSlot1 离线，资源超限样例仍呈现超限。
- S13 发射管编码与机型一致，中队数量、管道数量均在对应限制内。
- 移除指挥处理器后，按重算后的限制将超额脉冲装备离线；输出与保存内容均使用最终状态。
- 技能模板不保留上一轮等级/自定义覆盖；SDE 重载后重新读取模板。
- 编辑后不自动写入文件；同一次在线编辑连续手动保存时，仅更新一份本地副本，保留在线来源身份及最新装备状态。
- 保存状态通过持久化内容快照比较；修改后还原会清除未保存提示，技能、计算缓存和界面状态不参与比较。
- 新建/导入装配首次成功保存前始终未保存；在线查看无需保存确认，本地加载校验导致的实际内容差异仍可保存。
- 编码或文件写入失败保留原保存基准；重试成功、名称冲突自动递增后，以最终写入内容建立新基准。
- 用同一个计算器倒序重算全部 48 个装配，对比各自独立编辑器的结果，检查缓存污染。
  注意：必须传编辑器 simulationInput；output.originalInput 是 Step3 中间数据，不能重跑完整管线。
- 比较器自身验证数值变化、属性新增/删除、状态变化、NaN 和 SDE 变更均能被检测。
- FittingCalculationTests 覆盖叠加顺序、突变、实例身份、循环依赖、电容事件和换弹等边界公式。
- 属性影响明细检查生效实例、叠加系数、突变、预热、推进修正及跨计算清理；全部 48 个装配逐条验证明细连续且最终值与船体、装备、弹药、无人机和舰载机输出一致。

覆盖边界与已知行为
------------------
本套自动化保障上述计算管线在这些输入上的行为稳定，不宣称已经证明游戏数值完全正确，
也不替代全部功能的 UI 测试。场景人工操作步骤保留在 Fixtures 的 scenarios 中。
搜索/选择器、批量点击、导入导出格式、云端/API、价格、UI 展示和视图私有派生公式需要额外测试。
例如：仅修改 UI 的总 DPS/EHP/舰载机伤害汇总公式，不改变底层属性时，本套快照不会自动发现。

已知边界不应被“快照通过”解读为正确实现：
- 三神遥修预热采用“初始/完全”两档，不模拟逐周期预热过程或远程目标的实际受修结果。
- tubeId 的 0–99 为轻型管、100–199 为重型管、200 起为辅助管；当前模型没有独立储备状态。
- 建筑服务槽 S19 是模型边界，不能据此宣称 UI/EFT 已支持建筑装配。
- 药剂副作用选择是运行时状态，原生装配未保存；当前快照采用未启用副作用。
- 技能固定全 5；角色技能加载和技能模式切换交互不在本套自动化范围内。
